# 이미지 압축·형식 가이드 보강 및 로컬 검증

작업일: 2026-11-08 KST. 브랜치: `main`. 이번 작업은 로컬 수정과 검증까지이며 커밋·푸시·배포·GA4 설정 변경을 하지 않았다.

## 기존 상태와 확인한 부족한 내용

- 저장소와 상위 경로에서 별도 AGENTS.md 파일은 발견되지 않았다. 사용자가 제공한 한글 인코딩 보존 지침을 적용했다.
- 시작 시 추적 파일의 미커밋 변경은 없었다. 기존 미추적 `.codex-remote-attachments/`, `docs/ga4-custom-definitions-2026-11-07.md`, `docs/production-ga4-verification-2026-11-07.md`를 보존했다.
- 두 가이드는 기존부터 서버 컴포넌트였고 정적 생성 대상이었다. 자체 canonical, title/description, Open Graph, Twitter, Article JSON-LD, 가이드 목록과 하단 CTA가 있었다. URL·canonical·robots·사이트맵 생성 로직의 수정이 필요한 문제는 발견하지 못했다.
- 압축 가이드에는 ‘이미지 선택’, ‘품질 조절’ 정도의 일반적인 안내만 있어 실제 버튼명, 자동 처리 시점, 품질 적용 필요성, PNG의 WebP 출력과 원본 재사용 조건을 알기 어려웠다. KB·MB와 px의 구분, 목표 용량 기능 부재, 휴대폰·일괄 처리·다음 도구로 파일을 넘기는 방법이 부족했다.
- 형식 가이드는 JPG와 WebP 비교를 이미 제공했으나 PNG의 역할, 제출 사이트·투명 로고의 구체적인 선택, JPG 배경색 처리, 동일 형식 오류와 실제 자동 변환 순서가 부족했다.
- 과거 네이버 노출 41회/23회 및 클릭 0회는 과거 기준값으로만 취급했다. 현재 검색 통계를 조회하거나 사용자용 본문에 통계를 넣지 않았다.

## 코드에서 확인한 실제 기능

| 도구 | 확인한 동작 |
| --- | --- |
| 압축기 | JPG/JPEG·PNG·WebP 입력, 파일 추가 시 자동 처리. 품질 기본값 75, 범위 40~100, 간격 5. 슬라이더 변경 후 ‘품질 적용’ 필요. 픽셀 크기 유지. JPG·WebP는 같은 형식으로 압축하며 결과가 더 작지 않으면 원본 사용. PNG는 WebP로 출력하며 결과가 더 커질 수도 있음. 개별 및 ZIP 다운로드. 목표 KB 입력 기능 없음. |
| 변환기 | JPG/JPEG·PNG·WebP 입력과 JPG·PNG·WebP 출력. 추가 시 자동 처리, 출력 형식·JPG 배경색 변경 시 재처리, ‘변환 적용’ 지원. JPG 흰색·검정·사용자 지정 배경. PNG/WebP는 투명 영역 유지 가능. JPG/WebP 인코딩 품질은 코드에서 0.92이며 사용자 품질·무손실 선택 없음. 원본과 같은 형식은 오류. 목록 최대 30개, 이미지당 32,000,000픽셀. ZIP 이름 충돌에는 숫자 접미사 부여. |
| 크기 조절기 | 원본 MIME 형식으로 출력하고 투명 캔버스에 그리는 것을 코드에서 확인. 이번에는 별도 기능 확장이나 반복 운영 테스트를 하지 않음. |
| 자르기 | 관련 도구의 기존 경로를 확인하고 필요한 영역만 남기는 선택지로 연결. 이번에 새 자르기 사용법이나 기능을 구현하지 않음. |

## 남은 문제와 검증하지 못한 부분

1. **기존 압축기 ZIP 파일명 충돌을 재현했다.** `sample.png`, `sample.jpg`, `sample.webp`를 처리하면 PNG와 WebP 결과 이름이 둘 다 `sample-compressed.webp`가 되어 ZIP에 3개 대신 2개만 들어갔다. 도구 구현은 수정하지 않고 압축 가이드에 개별 다운로드 또는 서로 다른 이름 사용을 안내했다. 별도 도구 수정 단계가 필요한 기존 문제다.
2. **화면 캡처를 통한 시각 검토 미완료.** 기본 viewport/전체 화면 캡처와 하위 CDP 캡처 모두 `Page.captureScreenshot` 시간 초과가 발생했다. 탭이 visible/focused여도 동일했다. 따라서 DOM의 데스크톱·모바일 본문/링크/넘침 확인을 시각 검토 완료라고 표현하지 않는다. 배포 전에 실제 화면의 표 가로 스크롤·줄바꿈·색상·CTA 배치를 사람이 확인할 필요가 있다.
3. 실제 Android/iOS 사진 선택기·색상 선택기·파일 앱 동작은 검증하지 않았다. 30개 파일·32,000,000픽셀 제한 및 JPG/WebP 원본 반환 조건은 코드 확인이며 경계값 샘플 실험은 하지 않았다. 자르기·크기 조절 도구는 링크/응답 및 관련 코드 확인까지다.
4. 검색엔진 색인·현재 노출/클릭 변화, 순위 상승, AdSense 효과, GA4 정규 보고서 반영 여부는 이번 검증 범위 밖이다.

## 배포 전 검토 요약

본문·메타데이터·목록 안내만 바뀌며 URL과 기존 기능은 유지된다. 도구 처리·이벤트·광고 코드는 동일하다. 최종 3개 TSX 파일과 이 보고서만 이번 변경이며, 기존 미추적 보고서와 첨부자료는 배포 변경에 섞지 않았다. 시각 검토 제한과 압축기 ZIP 중복 문제를 배포 판단 시 함께 검토해야 한다. 이번에는 커밋·푸시·배포하지 않았다.

기술 설명 대조 자료:

- [MDN 이미지 형식 가이드](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types): JPG/PNG/WebP의 손실·투명도·용도와 호환성.
- [Google WebP 문서](https://developers.google.com/speed/webp): WebP의 손실·무손실·투명도 지원. 문서의 압축률 수치를 JSTools 성능 보장으로 사용하지 않음.
- [MDN canvas.toBlob](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob): 브라우저 출력 형식과 손실 형식의 품질 인수 의미.
