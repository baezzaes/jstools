# JSTools SEO 진단 및 로컬 개선 보고서

작업일: 2026-10-25 (한국 시간). 운영 사이트: https://jstools-app.vercel.app

코드 수정과 로컬 프로덕션 검증을 완료했습니다. Git 커밋·푸시·Vercel 배포는 하지 않았습니다. 운영 HTTP 결과는 기존 배포의 기준선이며 이번 수정의 배포 결과가 아닙니다.

## 1. 프로젝트 구조와 진단 범위

실제 설치 버전은 Next.js 16.2.12, React 19.1.0, TypeScript 5.8.2입니다. `package.json`은 Next.js `^16.2.12`, React `^19.0.0`, TypeScript `^5`를 선언합니다. App Router(`src/app`), Tailwind CSS 4, next-sitemap 4 계열을 사용합니다. Next.js 개발·빌드에는 Turbopack이 사용됩니다.

| 영역 | 현재 구현과 렌더링 |
| --- | --- |
| 홈·목록·가이드 | 서버 컴포넌트. 프로덕션 빌드에서 정적 HTML 생성 |
| 도구 12개 | `use client` 페이지지만 초기 HTML도 빌드 시 사전 렌더링. 계산·Canvas·파일 다운로드는 브라우저에서 실행 |
| 도구 메타데이터 | 각 도구 `layout.tsx`의 `generateMetadata()` → `src/lib/seo.ts` → `src/data/tools.ts` |
| 홈·가이드 메타데이터 | 각 서버 페이지의 `metadata` export, 루트의 `metadataBase` 및 공통 정보 |
| 구조화 데이터 | `ToolStructuredData`가 WebApplication·BreadcrumbList·FAQPage 생성. 개별 가이드 Article, 이미지 도구 목록 BreadcrumbList·ItemList |
| 사이트맵 | `npm run build`의 postbuild에서 next-sitemap 실행 → `public/sitemap.xml` 인덱스와 `public/sitemap-0.xml` URL 목록, robots.txt 생성 |
| 동적 SSR | 이번 빌드의 app 페이지는 모두 정적 생성으로 표시됨. `use client`를 본문 없는 CSR 전용 페이지로 판단하면 안 됨 |
| 환경과 분석 | Vercel 운영 도메인, GA4와 네이버 분석 스크립트가 루트에 존재. 실제 GitHub 연결과 Vercel 자동 배포 설정은 변경하거나 대시보드에서 재검증하지 않음 |

## 2. 실제 확인한 문제와 수정 전후

근거는 작업 시작 시 Git의 기존 소스와 운영 HTTP 응답, 수정 후 소스·로컬 빌드입니다. 크롤링·색인 차단 문제와 콘텐츠·사용 흐름 개선을 구분했습니다.

| 항목 | 수정 전 확인 근거 | 수정 후 | 의미 |
| --- | --- | --- | --- |
| 홈 canonical | 운영 `/` 및 UTM 응답에 canonical 없음 | 홈 페이지에 query 없는 canonical 추가 | 대표 URL 신호 보완. 기존 색인 실패 원인으로 단정하지 않음 |
| 홈 제목·설명 | `JSTools`, 짧은 공통 설명 상속 | 이미지·글자수·날짜 도구를 설명하는 제목·설명, OG·Twitter 보완 | 서비스와 검색 의도를 더 명확히 전달 |
| `/tools` | `도구 페이지` 제목만 있는 임시 본문, 자체 metadata 없음 | 기존 데이터로 도구 12개 실제 링크와 설명, 자체 metadata·canonical 추가 | 얇은 목록을 실제 탐색 허브로 개선 |
| 사이트맵 수정일 | next-sitemap 기본 autoLastmod가 모든 URL에 빌드 시각 기록 | autoLastmod 비활성화, daily를 monthly로 변경 | 코드 배포일을 콘텐츠 수정일로 오해시키는 신호 제거. 향후 실제 수정일을 관리할 때만 lastmod 재도입 |
| 이미지 가이드 CTA | 긴 설명·표·사용법 다음에 CTA | 첫 문단 아래 CTA 추가, 기존 하단 CTA 유지 | 모바일 첫 화면에서 바로 도구 사용 가능 |
| 이미지 설명 | 픽셀·압축 차이는 이미 설명됨 | 실제 버튼명, 2400→1200px 예시, 용량 자동 지정 미지원, 모바일 FAQ 보완 | 기능을 과장하지 않고 사용 의도를 구체화 |
| 이미지 내부 연결 | 관련 도구는 이미 존재하나 순서와 다음 행동 설명 부족 | 리사이즈→압축→변환→자르기 흐름 정리, 결과 파일을 직접 다시 선택한다고 안내, 도구→가이드 링크 추가 | 파일이 자동 전달되는 것으로 오해하지 않도록 안내. 규격상 필요하면 자르기를 먼저 하도록 설명 |
| 날짜 도구 | 일반적 사용법만 존재, view·execute 이벤트 호출 없음 | 날짜 예시·시작일 포함 기준·D-day 수동 활용 설명, 입력 접근성·모바일 배치, view·execute 추가 | 날짜 계산 기능은 유지. 알림·영업일 계산을 제공한다고 설명하지 않음 |
| 글자수 도구 | 영어 Word Counter 중심 제목, 작은 입력 글꼴 | 한국어 계산 의도에 맞춘 제목·설명, 자기소개서 사례와 계산 기준, 입력 16px·접근성 이름 | 공백·빈 줄·일부 이모지 계산 기준을 정확히 안내 |
| QR 도구 | 연락처·와이파이 활용 예시가 전용 기능처럼 보일 수 있음. 다운로드·옵션 안내 부족 | 실제 URL·텍스트→SVG 표시만 설명, 미지원 옵션과 다운로드 버튼 부재 명시, view·execute 추가 | PNG 다운로드 기능을 추가했다고 주장하지 않음 |
| QR 모바일 | SVG 고정 256px만 지정 | 최대 폭 100%, 높이 자동, 가운데 배치 | 320px에서도 넘침 없이 표시 |
| viewport | 루트 수동 태그와 Next.js 기본 태그 중복 | 수동 태그 1줄 제거, Next.js 기본 태그 사용 | 모바일 설정 중복 제거 |
| 구조화 데이터 의미 | 가이드 목록을 Article로 표현, 일부 breadcrumb 이름은 실제 `/tools` 페이지와 불일치 | CollectionPage + ItemList로 수정, `/tools` breadcrumb는 전체 도구 | 실제 페이지 유형과 경로를 일치시킴 |

사이트맵 누락이나 주요 도구의 noindex는 운영 검사에서 발견되지 않았습니다. 이미지 가이드는 이미 운영 사이트맵에 포함되며 본문도 초기 HTML에 존재합니다. 사이트맵 19개와 Search Console 색인 9개의 차이는 오류 10개를 의미하지 않습니다.

운영 기존 배포와 수정한 로컬 프로덕션 서버 모두에서 아래 경로의 일반 URL 및 UTM URL을 검사했습니다.

robots.txt는 `User-agent: *`, `Allow: /`이며 사이트맵 인덱스를 안내합니다. 주요 응답에서 `X-Robots-Tag: noindex`도 없었습니다. 루트 URL의 마지막 `/` 유무는 URL 정규화로 비교했습니다.

로컬 canonical 19개 전체에 대해 HTTP 200, 제목·설명 중복 없음, 자체 canonical, OG·Twitter 제목, 초기 HTML 텍스트, 내부 링크 목적지의 canonical 목록 포함을 검사했습니다. 유사한 가이드와 도구는 각각 설명과 실제 작업이라는 의도가 다르므로 서로 canonical로 합치지 않았습니다.

구조화 데이터는 JSON 구문과 본문 일치를 중심으로 검사했으며 Google Rich Results Test의 실제 서비스 검증은 실행하지 않았습니다. 기존 도구 FAQPage는 보이는 FAQ와 일치하도록 유지했습니다. 이미지 가이드에는 사용자용 FAQ를 추가하되 별도 FAQ JSON-LD를 늘리지 않았습니다. Google 공식 변경 이력에 따르면 FAQ 리치 결과는 2026-05-07부터 표시되지 않으므로 리치 결과 노출을 기대 효과로 주장하지 않습니다. [Google 공식 변경 이력](https://developers.google.com/search/updates)

## 4. GA4와 네이버 블로그 연결

`src/lib/analytics.ts`의 이벤트 이름과 기존 파라미터를 바꾸지 않았습니다.

| 이벤트 | 의미·발생 조건 | 기존 파라미터 |
| --- | --- | --- |
| guide_cta_click | GuideCtaLink 클릭. 새 상단 CTA도 같은 함수를 사용 | guide_name, target_tool, target_url |
| tool_view | 도구 진입. 현재 구현은 같은 문서 안에서 동일 경로를 Set으로 한 번만 기록 | tool_name, tool_category, tool_url |
| tool_execute | 도구별 실행 기준. 리사이즈는 파일 추가 자동 처리 및 크기 적용 시 각각 발생. 글자수는 첫 유효 입력 때 한 번 | tool_name, tool_category |
| download_click | 파일 다운로드 클릭. 성공 저장이나 실제 사용 완료를 보장하는 지표는 아님 | tool_name, file_type |

추가한 날짜 도구는 마운트마다 날짜 차이·전후 날짜의 두 모드에서 첫 결과를 표시할 때 각각 한 번 기록합니다. QR은 마운트마다 첫 비어 있지 않은 입력에 한 번 기록합니다. 따라서 이벤트 횟수와 고유 사용자·세션·다운로드 완료 수는 서로 다릅니다. 변경 이후 날짜·QR 이벤트가 늘어나는 현상은 측정 범위 확대 효과와 구분해 봐야 합니다.

입력 텍스트, QR에 넣은 URL, 날짜 값, 파일명, 이미지 바이트는 추가 이벤트 파라미터로 전송하지 않았습니다. 테스트에서도 이벤트 객체에 입력 데이터가 없는 것을 확인했습니다. GA4의 기본 페이지 URL 수집과 사용자 입력 내용 수집은 구분해야 하며, UTM 값에는 개인정보를 넣지 마세요.

블로그 링크 예시:

```text
https://jstools-app.vercel.app/tools/image/image-resizer?utm_source=naver_blog&utm_medium=referral&utm_campaign=image_resize&utm_content=post_001
```

UTM은 외부 링크에만 붙이고 사이트 내부 CTA에 새 UTM을 붙이지 않는 방식을 권합니다. canonical은 query 없는 도구 URL을 가리키므로 캠페인별 중복 페이지를 대표 URL로 구분하지 않습니다. 로컬에서는 UTM 직접 진입 상태에서 이미지 처리와 다운로드까지 확인했습니다. 8개 주요 경로의 UTM HTTP·메타데이터도 검사했습니다.

GA4에는 이미 gtag config가 있으므로 UTM을 모든 도구 이벤트에 수동으로 복사하는 코드는 추가하지 않았습니다. GA4에서 세션 소스/매체·캠페인·방문 페이지로 유입을 분리하고, 탐색 보고서에서 해당 세션의 tool_execute·download_click을 연결해 확인하세요. tool_name·tool_category·guide_name·target_tool 등을 탐색 차원으로 쓰려면 기존 맞춤 측정기준 등록 여부를 확인해야 합니다. [GA4 UTM 공식 안내](https://support.google.com/analytics/answer/10917952)

이 작업은 브라우저의 dataLayer 기록과 기존 이벤트 객체까지 검증했습니다. 외부 분석 스크립트를 차단해 테스트 이벤트가 운영 통계에 전송되지 않도록 했으므로, GA4 서버 수신·보고서 귀속·맞춤 차원 등록 상태는 검증하지 않았습니다. 네이버 앱 내장 브라우저와 실제 iOS·Android 기기에서 파일 선택·저장 권한 및 저장 위치도 별도 확인이 필요합니다.

브라우저 콘솔의 외부 광고·GA·네이버 스크립트 요청 실패는 테스트에서 의도적으로 차단한 결과입니다. 이를 운영 장애로 판단하지 않았고 광고 코드도 수정하지 않았습니다. CLI의 버튼 이름·인자 전달·비동기 완료 대기에서 생긴 테스트 실패는 수정 후 해당 흐름을 다시 확인했습니다. 일반 기능 전체·모든 이미지 형식·대용량·모든 OS·접근성 전체·성능 지표를 검증한 것은 아닙니다.

검증 산출물은 `output/playwright/`에 있으며 Git에서는 제외됩니다. 주요 파일은 `local-seo-audit.jsonl`, `production-baseline.jsonl`, `guide-mobile.png`, `date-mobile.png`, `word-mobile.png`, `qr-mobile-320.png`, `resizer-mobile.png`, `crop-mobile.png`입니다. 브라우저 흐름 스크립트와 실제 출력 파일도 같은 폴더에 보관했습니다.

재실행 예시 (최종 빌드 후 별도 터미널에서 로컬 서버 실행):

```powershell
npm.cmd run lint
npm.cmd run build
node node_modules/typescript/bin/tsc --noEmit
node node_modules/next/dist/bin/next start -p 3002
```

서버 실행 중 다른 터미널:

```powershell
$env:SEO_STRICT = '1'
node scripts/seo-audit.mjs http://localhost:3002
```

## 7. Search Console·네이버에서 직접 확인할 항목

1. 배포 승인 및 실제 배포 이후 정확한 속성에서 `/sitemap.xml`을 제출·재제출하고 마지막 읽음 시각, 가져오기 성공, 발견 URL 수를 비교합니다. 인덱스와 하위 사이트맵은 둘 다 접근 가능해야 합니다. 사이트맵은 발견을 돕는 신호이며 색인을 보장하지 않습니다. [Google 사이트맵 공식 안내](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
2. `/guide/image-resize` URL 검사에서 색인 여부·마지막 크롤링·실시간 테스트의 렌더링 HTML을 확인합니다. 발견됨-현재 색인되지 않음, 크롤링됨-현재 색인되지 않음, 중복, 차단 등 실제 사유를 확인한 뒤 대응합니다.
3. 사용자 선언 canonical과 Google 선택 canonical을 비교합니다. UTM URL은 clean canonical로 통합되는지 확인하고, 가이드와 도구는 별개 대표 URL로 유지합니다. canonical은 검색엔진이 고려하는 신호이며 선택을 강제하지 않습니다. [Google canonical 공식 안내](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)
4. 나머지 7개 우선 URL도 동일하게 검사하고 필요 시 주요 변경 URL의 색인 생성 요청을 진행합니다. 이번 작업에서는 요청·제출을 수행하지 않았습니다.
5. Google 소유권 확인 태그가 Search Console의 실제 발급값과 일치하는지 대조합니다. 소스에 있는 값을 추측해 교체하지 않았습니다. 네이버 소유권 태그도 유지했습니다.
6. 네이버 Search Advisor에서 사이트맵 수집, 주요 URL 수집·색인과 검색 노출을 직접 확인합니다. 해당 계정 상태와 네이버의 실제 색인은 이번 작업에서 확인하지 못했습니다.

## 8. 다음 개선과 네이버 블로그 홍보 우선순위

사용자가 제공한 2026-10-25 운영 수치는 이 작업에서 계정에 접속해 재집계한 값이 아닙니다. 최근 28일 GA4 활성 사용자 26·세션 30·PV 45, 실행 41·다운로드 클릭 20·가이드 CTA 14, 네이버 검색 관련 24세션이라는 기준선을 참고했습니다. GSC 최근 3개월 클릭 2·노출 143·CTR 1.4%·평균 순위 37.1, 날짜 86·리사이즈 27·글자수 13·QR 10회 노출도 사용자 제공 자료입니다.

기간과 분모가 다른 값을 직접 나누거나 CTA 14회를 14명의 전환으로 해석하지 마세요. 현재 표본에서는 제목 변경의 순위 효과를 단정하기 어렵습니다. 배포 후 2~4주 단위로 페이지·검색어별 노출/클릭, 유입 세션 중 도구 실행 세션 비율, 실행 세션 중 다운로드 클릭 세션 비율을 비교하는 방식을 권합니다.

| 우선순위 | 도구·블로그 주제 | 선정 이유와 연결 |
| --- | --- | --- |
| 1 | 이미지 크기 조절기 — 휴대폰 사진 가로 픽셀을 줄이는 방법 | 현재 가이드·도구 방문 집중. 실제 전후 픽셀 예시를 보여주고 상단 또는 단계 직후 직접 도구 링크 제공 |
| 2 | 이미지 용량 줄이기 — 사진 픽셀과 KB 용량의 차이 | 리사이즈 다음 의도와 연결. PNG가 WebP로 저장되는 점, 용량 감소가 항상 보장되지 않는 점을 설명 |
| 3 | 날짜 계산기 — 오늘부터 30일 후·마감일까지 남은 일수 | 사용자 제공 GSC에서 노출 86회로 가장 많음. 직접 날짜 입력 예시와 시작일 제외·주말 포함 기준 안내 |

글자수 계산기는 다음 실험 후보로 자기소개서 공백 포함·제외 기준 콘텐츠를 권합니다. QR은 다운로드 요구가 예상되는 글보다 URL을 화면에서 바로 공유하는 사용 사례에 맞추는 편이 현재 기능과 일치합니다. QR 다운로드 기능은 별도 제품 개선으로 검토할 수 있으나 이번 SEO 작업에서 추가하지 않았습니다.

새 글을 대량 생성하기 전에 네이버 실제 검색어·경쟁 결과·독자 질문으로 주제를 검증하고, 기존 가이드에 실제 작업 예시를 보강하는 순서를 권합니다. OG 이미지나 LCP/INP 개선은 추가 측정 후 결정할 수 있는 제안이며 이번 진단에서 검색 차단 문제로 확인된 항목은 아닙니다.
