## 1단계: 사이트 안내 페이지

- `/privacy`: 도구 입력과 이미지의 브라우저 처리, localStorage, GA4·네이버 분석, 광고 쿠키와 개인화 해제 안내, 외부 서비스·문의 연락처
- `/about`: 실제 지원 도구, 운영 방식과 사용상 주의사항
- `/contact`: 확인된 이메일, 오류 제보에 필요한 정보와 개인정보 관련 문의 방법
- 모든 페이지의 공통 footer에서 접근 가능
- 각 페이지에 고유 metadata와 canonical 제공, 빌드 후 사이트맵 포함 확인

정책 문구는 현재 코드에서 확인한 데이터 흐름을 기반으로 작성했다. 계정에 설정된 GA4 보관 기간, 이메일의 실제 보관·삭제 운영, 광고 파트너와 국외 처리 세부조건은 소스만으로 확인할 수 없다. 실제 설정과 운영을 대조해 추가로 구체화해야 하며, 페이지 생성만으로 모든 법적 요건이나 AdSense 승인을 보장하지 않는다.

## 2단계: 게시자 인증과 ads.txt

`public/ads.txt`:

```text
google.com, pub-7836056065911594, DIRECT, f08c47fec0942fa0
```

배포 후 `https://jstools-app.vercel.app/ads.txt`가 HTTP 200과 위 한 줄을 반환하는지 확인한다. 기존 공통 AdSense 스크립트의 게시자 ID와 일치한다. ads.txt는 필수 승인 요건이라고 단정하지 않으며 계정의 상태 반영에는 시간이 걸릴 수 있다.

## 3단계: 실제 광고 단위 확인

현재 홈 및 여러 도구의 수동 광고 영역에 `data-ad-slot="1234567890"`이 있다. 사용자는 게시자 ID만 확인했으며 이 광고 단위 ID는 계정에서 확인되지 않았다. 실제 발급받은 광고 단위와 대조하기 전 임의 ID로 바꾸거나 유효하다고 단정하지 않는다.

자동 광고와 수동 광고는 별도 설정이다. 수동 광고의 slot 값을 지운다고 자동 광고가 되는 것은 아니다. 이번 준비 단계에서는 기존 광고 코드와 계정의 자동 광고 설정을 변경하지 않았다.

## 4단계: AdSense에서 사용자가 확인할 순서

1. 홈의 ‘시작하기’ 또는 왼쪽 메뉴 ‘사이트’로 이동한다.
2. 목록에서 `jstools-app.vercel.app`을 선택한다. 이미 항목이 있으면 중복 등록하지 않는다.
3. 사이트 연결·소유권 확인 화면에서 계정이 제공한 게시자 ID와 사이트 코드를 비교한다. 현재 사이트에는 해당 게시자 ID의 스크립트가 있다.
4. 이번 안내 페이지와 ads.txt가 운영에 반영된 뒤, 연결 확인을 진행한다. 검토 요청 버튼이 있는 경우 내용을 확인하고 요청한다. 이미 ‘검토 중’이면 같은 요청을 반복하지 않는다.
5. ‘검토 필요’라면 화면의 구체적인 조치 사유를 먼저 확인한다. ‘준비됨’ 상태는 이 코드 작업으로 자동 보장되지 않는다.

## 5단계: 동의 관리와 광고 활성화

- EEA·영국·스위스 이용자에게 개인 맞춤 광고를 제공할 경우 Google 인증 CMP 요건을 확인한다.
- AdSense ‘개인정보 보호 및 메시지’에서 Google의 유럽 규정 메시지 사용 여부와 게시자 ID를 확인하고, 표시할 사이트에 JSTools를 연결한다.
- 동의·거부·선택 변경 경로와 GA4 동의 신호 연계를 실제 브라우저에서 점검한다. 한국어 개인정보처리방침 링크만으로 CMP가 설정되는 것은 아니다.
- 광고 노출 전 사이트 상태가 ‘준비됨’인지 확인한다.
- 자동 광고를 사용할지 수동 광고 단위를 사용할지 결정하고, 수동 단위를 사용하면 계정에서 발급한 실제 slot ID를 적용한다.
- 모바일에서 파일 선택·입력·결과·다운로드를 가리거나 광고 클릭을 유도하는 배치가 없는지 확인한다. 본인 광고를 테스트 클릭하지 않는다.
